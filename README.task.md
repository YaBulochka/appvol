# Задача: appvol — громкость активного окна по хоткею (KDE Plasma 6 / Wayland / PipeWire)

Исходное техническое задание, сохранено без изменений. Текущий результат описан в `README.md`.

## Контекст
Пользователь на KDE Plasma 6.7.x, Wayland, PipeWire + pipewire-pulse. Есть рабочий PoC `spotify-volumeup.sh`
(парсит `wpctl status`, жёстко зашиты Spotify/mpv, OSD через qdbus). Нужно заменить его нормальным проектом.
Прочитай PoC, пойми, что он делает, и не повторяй его слабые места (парсинг текстового вывода, хардкод приложений).

## Цель №1 (делаем только её)
Команда `appvol up|down|mute` меняет громкость **всех аудиопотоков приложения, окно которого сейчас в фокусе**
и показывает KDE OSD. Команда вешается пользователем на хоткей в System Settings → Shortcuts → Add Command.

Позже (НЕ сейчас, но не закрывай себе дорогу): закреплённые правила по потокам из GUI, группы с приоритетом,
Qt GUI, GlobalShortcuts portal. Слой «цель → список потоков» делай отдельным модулем, чтобы потом добавить
цели `rule:<id>` и `group:<id>` рядом с `active`.

## Архитектура
- **Демон `appvold`** (Python 3.11+): держит подключение к pipewire-pulse через `pulsectl`, регистрирует D-Bus сервис
  `org.appvol.Daemon`, хранит в памяти последний фокус окна. Один инстанс (имя на шине занято → выход).
  Автоперезапуск соединения с pulse при рестарте pipewire-pulse.
- **KWin-скрипт** (push): на старте и на каждый `workspace.windowActivated` вызывает через `callDBus`
  метод демона `SetFocus(pid, resourceClass, desktopFileName, caption)`. Если активного окна нет, шлёт пустой фокус.
  Демон сам загружает скрипт: `org.kde.KWin /Scripting loadScript(path, "appvol")` + `run()`, на выходе `unloadScript`.
  Следит за `NameOwnerChanged` для `org.kde.KWin` и перезагружает скрипт после рестарта KWin.
- **CLI `appvol`**: тонкий клиент, зовёт метод демона по D-Bus и выходит. Отклик на нажатие <50 мс.
  Никаких запросов в KWin на нажатие, фокус берётся из кэша демона.
```
  appvol up|down [--step 5]
  appvol mute
  appvol list        # потоки, текущий фокус и какие потоки с ним сматчились
```
- Опционально systemd user unit для демона.

## Сопоставление окно → потоки
Потоки = sink-input'ы. Результат — список. От точного к грубому, остановиться на первом шаге, давшем результат:
1. `application.process.id` == pid окна.
2. pid потока — потомок pid окна (ppid-цепочка через `/proc/<pid>/stat`): Firefox/Chromium/Electron.
3. Имя: `desktopFileName` / `resourceClass` окна против `pipewire.access.portal.app_id`, `application.id`,
   `application.process.binary`, `application.name` (case-insensitive, `org.mozilla.firefox` ↔ `firefox`, без `.desktop`).
Нет потоков → ничего не менять, без ошибки, в verbose-логе написать причину.
Фокус на панели/рабочем столе/plasmashell → игнорировать.

## Громкость и OSD
- Шаг относительный (по умолчанию 5%, конфигурируемый), применяется ко всем найденным потокам, баланс каналов сохраняется.
- Клэмп 0–100% (лимит в конфиге, можно до 150%).
- `mute` — тоггл у всех найденных потоков.
- OSD: `org.freedesktop.Notifications /org/kde/osdService org.kde.osdService.volumeChanged <percent>`
  (в PoC это работает). Процент = максимум по изменённым потокам. Для mute можно `showText`, если доступен.
- Не парсить вывод `wpctl`/`pactl` текстом. Использовать `pulsectl`.

## Конфиг
`~/.config/appvol/config.toml`: `step`, `max_volume`, `osd` (on/off). Нет файла → дефолты.

4. Громкость + OSD.
5. Перезагрузка скрипта при рестарте KWin, reconnect к pulse.

## Критерии готовности (проверять руками и по возможности автотестами на чистой функции матчинга)
- Фокус на Spotify → `appvol up` поднимает только громкость Spotify, OSD показывает итоговый процент.
- Фокус на Firefox с играющим видео → меняются все его потоки (дочерние процессы).
- Фокус на окне без звука → ничего не происходит, ошибок нет.
- `appvol up` отрабатывает <50 мс при уже запущенном демоне.
- После `kwin_wayland --replace` фокус снова доходит до демона без ручных действий.
- Поведение для «Spotify/mpv» из PoC воспроизводится при фокусе на соответствующем окне.

## Правила
- Без root, без X11-инструментов (`xdotool` и т.п.).
- Минимум зависимостей, структура: `appvol/{daemon,focus,match,volume,osd,cli}.py` + `kwin/appvol.js`.
- Матчинг и расчёт громкости как чистые функции, на них unit-тесты.
- Код и логи на английском, README на русском.
- Не реализовывать GUI, правила, группы и portal. Только цель №1.
- Если решение неочевидно или API KWin ведёт себя странно, остановись и коротко опиши проблему, не городи обходные костыли молча.
